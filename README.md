# fortune-alarm-template — 매일 아침 내 운세 알림

설정 파일 하나(`me.yaml`)와 시크릿 3개만 넣으면, 매일 아침 텔레그램으로 그날의 운세(사주 + 서양 별자리)가 옵니다.

계산은 코드(결정론적, 환각 0), 해석은 Claude가 생성한다.

- **계산** — 사주 네 기둥, 대운, 그날의 일진, 오늘 하늘의 행성 위치는 천문 계산으로 구합니다. 같은 입력이면 언제 돌려도 같은 값이 나옵니다.
- **해석** — Claude가 계산된 값만 근거로 쉬운 말의 해요체 메시지를 만들고, 발송 전에 품질 게이트가 굳은 문장 틀·전문용어·서식 기호를 검사합니다. 걸리면 최대 두 번 다시 쓰게 하고, 그래도 남으면 그대로 보냅니다. 다만 끊기거나 거절로 끝난 글, 필수 부분이 빠진 글은 보내지 않습니다.
- **실행** — GitHub Actions가 매일 돌립니다. 내 컴퓨터를 켜 둘 필요가 없습니다.

> 예시 인물 '하늘'·'바다'는 지어낸 사람입니다. `me.yaml`을 내 정보로 바꿔 쓰세요.

## 15분 설치

### ① Use this template으로 복사 — 반드시 Private

저장소 오른쪽 위 **Use this template → Create a new repository**를 누르고, 이름을 정한 뒤 **Private**을 고르고 만듭니다.

`me.yaml`에는 생년월일시가 들어갑니다. 매일 아침 발송문은 저장소의 `state/` 폴더에 커밋되고, 실행 기록(Actions 로그)에는 명식 점검 출력(생년월일시·네 기둥·대운·별자리 세 축·확인할 점)과 그날의 발송문 전체가 남습니다. 공개(Public) 저장소면 누구나 이 모두를 볼 수 있으니 반드시 Private으로 둡니다. 이미 Public으로 만들었다면 Settings 맨 아래 **Change repository visibility**에서 Private으로 바꾼 뒤 다음 단계로 갑니다.

### ② 시크릿 3개 넣기

새 저장소의 **Settings → Secrets and variables → Actions → New repository secret**에서 셋을 하나씩 넣습니다.

| 이름 | 값 | 어디서 |
|---|---|---|
| `ANTHROPIC_API_KEY` | Claude API 키 | Anthropic 콘솔(Claude Console)에서 만듭니다 |
| `TELEGRAM_BOT_TOKEN` | 내 텔레그램 봇 토큰 | 텔레그램에서 @BotFather에게 `/newbot`을 보내 봇을 만들면 줍니다 |
| `TELEGRAM_CHAT_ID` | 내 텔레그램 chat id(숫자) | 아래 방법으로 찾습니다 |

**chat id 찾기.** 텔레그램 봇은 먼저 말을 걸 수 없습니다. 내 봇을 열어 **시작(/start)**을 누르거나 아무 말이나 한 번 보낸 뒤, 24시간 안에 둘 중 하나로 찾습니다.

- 브라우저 주소창에 `https://api.telegram.org/bot<봇 토큰>/getUpdates`를 넣고 열어 `"chat":{"id":` 다음 숫자를 봅니다. 주소에 토큰이 들어가니 남의 컴퓨터에서는 하지 마세요. `<봇 토큰>` 자리는 꺾쇠(`<`, `>`)까지 지우고 토큰만 넣습니다.
- 내 컴퓨터에 파이썬이 있으면 이 폴더의 `.env`에 `TELEGRAM_BOT_TOKEN=...`를 한 줄 넣고 `python find_chat_id.py`를 실행합니다(설치 없이 돕니다).

### ③ me.yaml 고치기

GitHub 웹에서 `me.yaml`을 열고 연필 모양(Edit)을 눌러 내 정보로 바꾼 뒤 **Commit changes**를 누릅니다. 칸마다 한 줄 설명이 붙어 있습니다.

| 칸 | 적는 것 |
|---|---|
| `name` | 이름. 로그와 최근 발송문 파일 이름에 쓰입니다 |
| `birth.date` | 생년월일(**양력**) `YYYY-MM-DD`. 음력으로 알고 있으면 양력으로 바꿔 적습니다 |
| `birth.time` | 태어난 시각 `HH:MM`(24시간제). 모르면 아래 [출생 시각을 모를 때](#출생-시각을-모를-때) |
| `birth.place` | 태어난 시 이름. [지역 목록](#지역-목록)에 없으면 `lat`·`lon`(위도·경도) |
| `gender` | `여` 또는 `남` — 대운이 흐르는 방향이 이 값으로 정해집니다 |
| `hour_rule` | 자시 경계 관례 `A`·`B`·`C`. 모르면 `A` ([자시 경계와 세 가지 관례](#자시-경계와-세-가지-관례)) |
| `chat` | 받을 곳. `me`면 `TELEGRAM_CHAT_ID`로 보냅니다 |
| `honorific` | 메시지에서 부를 호칭(예: 하늘님). 비우면 부르지 않습니다 |

잘못 적으면 실행할 때 무엇을 어떻게 고치라는 한 문장이 나오고 멈춥니다. 날짜 형식, 목록에 없는 지역, 성별 오타, 음력 표기, 철자가 틀린 칸 이름이 모두 여기서 걸립니다.

### ④ Actions에서 수동 실행

**Actions** 탭 → 왼쪽 **daily-fortune** → **Run workflow**를 누릅니다. 워크플로를 켤지 묻는 버튼이 보이면 먼저 눌러 켭니다.

- `dry_run`을 체크하면 텔레그램으로 보내지 않고, 실행 기록에서 점검 출력과 해석문을 볼 수 있습니다. 점검 출력(네 기둥·관례별 후보·대운·별자리 세 축·확인할 점)은 **내 명식 점검 (me.yaml)** 단계에, 해석문은 **Send daily fortune** 단계에 있습니다. 해석문을 만들려고 Claude는 부릅니다.
- 체크하지 않으면 실제로 보냅니다.

### ⑤ 텔레그램 확인

몇 분 안에 텔레그램으로 메시지가 옵니다. 그다음부터는 매일 아침 자동으로 옵니다.

안 오면 Actions 실행 기록에서 **내 명식 점검 (me.yaml)** 단계와 **Send daily fortune** 단계를 엽니다. 예약이 늦거나 그날 실행이 아예 없으면 아래 [늦게 오거나 안 올 때](#늦게-오거나-안-올-때)를 봅니다.

| 기록에 보이는 줄 | 뜻과 할 일 |
|---|---|
| `[me.yaml] ...` | 설정 파일 문제. 그 문장대로 `me.yaml`을 고칩니다(점검 단계에서 멈춥니다) |
| `[설정] 시크릿 TELEGRAM_BOT_TOKEN이 비어 있습니다` | 봇 토큰 시크릿을 넣습니다. Claude는 부르지 않고 멈춘 것입니다 |
| `[설정] 시크릿 TELEGRAM_CHAT_ID가 비어 있습니다` | 내 chat id 시크릿을 넣습니다(맨 위 사람이 받을 곳) |
| `chat_id 없음 (FORTUNE_CHAT_IDS의 ...)` | 가족·친구의 받을 곳이 비어 그 사람만 건너뛰었습니다 |
| `ANTHROPIC_API_KEY 환경변수가 필요합니다` | Claude API 키 시크릿이 비었습니다 |
| `[telegram] 거절 HTTP 401` 또는 `HTTP 404` | 봇 토큰이 틀렸습니다. BotFather가 준 토큰을 시크릿에 다시 넣습니다 |
| `[telegram] 거절 HTTP 400: Bad Request: chat not found` | chat id가 틀렸거나, 받는 사람이 내 봇에서 시작(/start)을 누르지 않았습니다 |
| `[telegram] 거절 HTTP 403` | 받는 사람이 봇을 차단했거나 아직 시작(/start)을 누르지 않았습니다 |
| `[telegram] 발송 포기` | 텔레그램이 한동안 응답하지 않았습니다(시간 초과·서버 오류). 잠시 뒤 다시 실행합니다 |
| `끝까지 온전한 글이 없어 보내지 않음` | Claude의 응답이 끊기거나 거절로 끝났습니다. 다시 실행합니다 |
| `이미 발송됨 (state에 오늘 날짜)` | 오늘 이미 보냈습니다. 같은 날 다시 보내지 않습니다(요금이 두 번 나가지 않게) |

실패하거나 실행이 중간에 취소되면 내 텔레그램으로 알림이 한 줄 옵니다.

## 가족·친구 추가

`me.yaml`의 `people:` 아래에 사람을 더 적으면 그 사람 몫의 운세도 매일 만듭니다. 받을 곳은 둘 중 하나입니다.

- **내 텔레그램으로 같이 받기** — `chat: me`. 가족은 아무것도 설치하지 않아도 됩니다.
- **그 사람 텔레그램으로 보내기** — 그 사람이 내 봇에 시작(/start)을 누르고, 내가 그 chat id를 시크릿 `FORTUNE_CHAT_IDS`에 JSON 한 줄(`{"bada": "숫자"}`)로 넣은 뒤 `me.yaml`에 `chat: bada`를 적습니다.

받아야 할 정보와 순서는 [ADDING_A_RECIPIENT.md](ADDING_A_RECIPIENT.md)에 있습니다. 맨 위 사람(본인)의 발송이 실패하면 실행 전체가 실패로, 나머지 사람만 실패하면 부분 실패로 표시됩니다. 한 사람의 실패가 다른 사람의 발송을 막지 않습니다.

## 자시 경계와 세 가지 관례

사주의 하루는 자시(子時)에서 시작하는데, 밤 11시부터 새벽 1시 사이에 태어난 사람은 그날을 어느 날로 볼지 유파마다 다릅니다. `hour_rule`이 그 관례를 고릅니다.

| 관례 | 시주(태어난 시의 기둥) | 일주(태어난 날의 기둥) |
|---|---|---|
| **A** | 진태양시(경도와 균시차로 고친 태양 시각)로 정한다 | 그날로 둔다 |
| **B** | 벽시계 시각으로 정한다 | 밤 11시대 출생이면 다음날로 넘긴다 |
| **C** | 벽시계 시각으로 정한다 | 그날로 둔다(야자시) |

일주가 갈리는 것은 벽시계 23시대 출생뿐입니다. 0시대는 달력 날짜가 이미 넘어가 있어 어느 관례든 같습니다. 예시 인물 바다(1988-07-09 23:40 부산)는 세 관례가 이렇게 갈립니다.

```
A 을축/정해 · B 병인/무자 · C 을축/병자      (일주/시주)
```

어느 쪽인지 모르면 **예전에 사주를 본 적이 있는지** 물어 그때 나온 일간(일주의 첫 글자)과 맞는 관례를 고르는 것이 가장 빠릅니다. 본인이 평소 쓰는 명식과 어긋나는 운세는 틀린 운세입니다. 경계에 걸리지 않는 사람은 세 관례가 같은 값을 내니 `A`로 두면 됩니다.

내 명식이 경계에 걸리는지는 점검 출력(사람마다 원국·관례별 일주와 시주·대운·별자리 세 축·확인할 점)으로 봅니다.

### 파이썬이 없어도 점검하는 법

깃허브 웹에서만 설치했다면 Actions에서 수동 실행할 때 `dry_run`을 체크합니다. 보내지 않고, 실행 기록의 **내 명식 점검 (me.yaml)** 단계에 점검 출력이, **Send daily fortune** 단계에 해석문이 남습니다. 매일 아침 예약 실행의 기록에도 같은 점검 출력이 남습니다.

### 내 컴퓨터에서 점검하기(요금 없음)

```bash
pip install -r requirements.txt     # 처음 한 번 — 필요한 패키지 설치
python -X utf8 me_config.py         # 점검 출력 (Claude를 부르지 않는다)
```

점검 출력의 `확인 필요:` 줄은 이런 때 나옵니다.

- **표준시 보정** — 1908-04-01부터 1911-12-31까지와 1954-03-21부터 1961-08-09까지(UTC+8:30), 그리고 1948–1951년·1955–1960년·1987·1988년 여름 서머타임 기간에 태어난 사람은 벽시계 시각을 그대로 쓰면 틀립니다. 코드가 자동으로 고치고 그 사실을 알려 줍니다. 1908-04-01 전 출생은 표준시 기준이 달라 보정하지 않고, 막지도 않습니다. 대신 시주가 어긋날 수 있다는 `확인 필요:` 줄을 띄웁니다.
- **절기 경계** — 절입 시각에서 하루 안쪽으로 태어났으면 월주(입춘 부근이면 띠까지)가 갈릴 수 있습니다.

## 출생 시각을 모를 때

이 템플릿은 태어난 시각 없이는 시주와 상승점을 계산하지 못합니다. 출생신고서나 가족의 기억으로 `HH:MM`을 찾아 넣으세요. 끝내 모르면 `12:00`을 넣으면 계산은 돌지만, 그때는 시주와 상승점이 실제와 다를 수 있습니다.

## 지역 목록

`birth.place`에 쓸 수 있는 이름입니다(시·군 단위면 충분합니다).

서울 · 인천 · 수원 · 춘천 · 강릉 · 청주 · 대전 · 세종 · 천안 · 전주 · 광주 · 목포 · 여수 · 순천 · 대구 · 포항 · 안동 · 울산 · 부산 · 창원 · 마산 · 진주 · 제주

목록에 없는 곳, 또는 경기도 광주처럼 이름이 같은 다른 곳이면 `place`에는 아무 이름이나 적고 그 아래에 `lat`·`lon`을 함께 적습니다. `광주시`라고만 쓰면 경기도 광주시인지 광주광역시인지 알 수 없어 점검이 멈추고 어느 쪽인지 묻습니다.

```yaml
    birth:
      date: 1992-03-14
      time: 10:10
      place: 우리 동네
      lat: 36.6
      lon: 127.5
```

## 보내는 시각

예약은 `.github/workflows/daily-fortune.yml`에 두 줄 있습니다. GitHub의 예약은 기본이 UTC라 한국 시간에서 9시간을 뺀 값으로 적습니다.

- `cron: '47 21 * * *'` — 한국 시간 아침 6시 47분, 본 발송
- `cron: '17 22 * * *'` — 한국 시간 아침 7시 17분, 예비

아침 6시 47분에 한 번, 그때 못 보냈으면 7시 17분에 한 번 더 시도합니다. 이미 보냈으면 그냥 끝납니다(같은 날 가드). 본 발송이 늦어져 두 실행이 겹치면, 늦게 시작한 쪽이 앞 실행이 끝날 때까지 기다렸다가 같은 방식으로 건너뜁니다. 다만 보낸 뒤 기록 저장(**Commit state**)의 push가 세 번 다 실패했거나 실행이 중간에 취소된 날은 저장소에 그날 기록이 남지 않아 예비 실행이 한 번 더 보낼 수 있습니다. 그런 날은 실패 알림이 텔레그램으로 먼저 옵니다.

매시 정각은 Actions가 붐비는 시각이라 피해서 47분과 17분으로 잡았습니다(아래 '늦게 오거나 안 올 때'). 시각을 바꿀 때는 두 줄을 함께 바꿉니다(예: 본 발송 아침 6시 17분, 예비 6시 47분이면 `17 21 * * *`와 `47 21 * * *`).

## 늦게 오거나 안 올 때

GitHub 문서에 따르면 예약 실행은 Actions가 붐비는 때(매시 정각이 그런 때입니다) 늦게 시작될 수 있고, 아주 붐비면 대기 중인 실행 일부가 빠질 수도 있습니다. 그래서 예약을 두 번 걸어 두었습니다. 6시 47분 실행이 빠지거나 실패하면 7시 17분 예비 실행이 한 번 더 시도합니다. 두 번 다 빠진 날은 실행 자체가 없어서 실패 알림도 오지 않습니다.

실패 알림은 발송과 같은 봇 토큰과 내 chat id로 가므로, 이 두 시크릿이 비어 있거나 틀리면 알림도 오지 않고 Actions 탭의 빨간 실패 표시로만 알 수 있습니다(깃허브 알림 설정에 따라 메일이 오기도 합니다).

- **오늘 것이 안 왔으면** — Actions 탭 → 왼쪽 **daily-fortune** → **Run workflow**를 `dry_run` 체크 없이 누릅니다. 오늘 이미 보냈다면 같은 날 가드가 다시 보내지 않습니다.
- **더 일찍 받고 싶으면** — 위 '보내는 시각'에서 두 예약 줄의 분과 시를 함께 바꿉니다.
- **정시가 중요하면(윈도 컴퓨터)** — 내 컴퓨터의 작업 스케줄러가 정한 시각에 깃허브에 수동 실행을 요청하게 하고, 깃허브 예약 두 줄은 예비로 둡니다. 여러 실행이 돌아도 같은 날 가드 덕분에 두 번 가지 않습니다(실행이 겹치면 뒤의 실행이 앞의 실행을 기다렸다가 그날 보낸 기록을 보고 건너뜁니다). 그 시각에 컴퓨터가 켜져 있어야 요청이 갑니다. 아래 명령은 이 수업에서 도움말로 문법만 확인했으니, 등록한 뒤 5번으로 직접 시험해 보세요.

  1. 깃허브 CLI(`gh`)를 설치하고 한 번 로그인합니다: `gh auth login`
  2. 요청이 되는지 시험합니다: `gh workflow run daily-fortune.yml --repo <내 계정>/<저장소 이름>`
  3. 메모장으로 `C:\fortune\run.cmd` 파일을 만들고 2번 명령 한 줄을 넣습니다(`C:\fortune` 폴더가 없으면 먼저 만듭니다).
  4. 명령 프롬프트에서 매일 06:30에 그 파일을 돌리게 등록합니다:

     ```
     schtasks /Create /SC DAILY /TN fortune-alarm /TR C:\fortune\run.cmd /ST 06:30
     ```

  5. 등록이 됐는지 바로 시험합니다: `schtasks /Run /TN fortune-alarm` — 잠시 뒤 Actions 탭에 새 실행이 생기면 된 것입니다(오늘 이미 보냈으면 그 실행은 보내지 않고 끝납니다).
  6. 그만두려면: `schtasks /Delete /TN fortune-alarm`

  맥·리눅스용 예약 명령은 이 수업에서 직접 확인하지 못해 싣지 않았습니다.

## 로컬에서 돌리기

파이썬 3.10 이상이 필요합니다. 윈도에서는 한글 출력이 깨지지 않게 `python -X utf8`로 실행합니다.

```bash
pip install -r requirements.txt
python me_config.py                          # me.yaml 점검 — 요금 없음
python -X utf8 -m pytest -q                  # 회귀 테스트 — 요금 없음, 네트워크 없음
cp .env.example .env                         # 값을 채운다(.env는 git에 올라가지 않는다)
python -X utf8 run_daily.py --dry-run        # 운세를 만들어 화면에만 — Claude 요금이 듭니다
python -X utf8 run_daily.py                  # 실제 발송
```

`--date 2026-11-15`로 날짜를, `--people 하늘`로 사람을 고를 수 있습니다. 오늘 이미 보낸 사람에게 다시 보내려면 `--force`를 붙입니다.

## 계산 검증 도구(선택, 수업 4장 3강)

`tools/verify_with_de421.py`는 이 봇이 pyephem으로 낸 행성 위치를 NASA JPL 천문력 DE421과 각초 단위로 대조합니다. 매일 알림에는 필요 없습니다. 도구는 DE421 파일을 스스로 내려받지 않으니, 처음 한 번 아래 순서로 받아 둡니다(Skyfield 공식 문서의 방법).

```bash
pip install -r requirements-verify.txt
python -c "from skyfield.api import load; load('de421.bsp')"    # 이 폴더에서 한 번 — Skyfield가 de421.bsp(약 17MB)를 이 폴더에 받는다
python -X utf8 tools/verify_with_de421.py 2026-11-14 de421.bsp --retro-scan
```

받은 `de421.bsp`는 `.gitignore`에 있어 저장소에 올라가지 않습니다. 천문력 파일은 갱신되지 않으니 한 번 받으면 다시 받을 필요가 없습니다.

## 요금

Claude API는 쓴 만큼 요금이 나갑니다. 한 번 실행에 사람마다 Claude를 한 번 부르고, 품질 게이트에 걸리면 최대 두 번 더 부릅니다. 예비 실행은 그날 이미 보낸 사람에게 Claude를 부르지 않습니다.

비공개 저장소의 GitHub Actions에는 무료 사용 한도가 있습니다. GitHub 문서(2026-11-14 확인)에 따르면 GitHub Free 요금제에는 매달 12달러어치의 사용량이 포함되고, 리눅스 2코어 실행기의 요금은 1분에 0.006달러입니다. 이 워크플로는 리눅스(`ubuntu-latest`)에서 하루 두 번(본 발송과 예비) 돕니다. 이미 보낸 날의 예비 실행은 설치·점검·테스트를 마치고 바로 끝나지만, 그 시간도 사용량에 들어갑니다. 결제 수단을 등록하지 않은 계정은 포함된 사용량을 다 쓰면 실행이 막힙니다. 금액과 한도는 바뀔 수 있으니 수업자료와 GitHub 문서를 함께 확인하세요.

## 해석 모델 바꾸기

기본 모델은 `interpret.py`의 `DEFAULT_MODEL` 한 곳에 있습니다. `me.yaml` 맨 위의 `# model:` 줄에서 `#`와 그 뒤 공백 한 칸을 지우고 다른 Claude 모델 이름을 적으면 그 모델을 씁니다.

## 이 폴더의 파일

| 파일 | 하는 일 |
|---|---|
| `me.yaml` | 설정 — 사람·출생정보·받을 곳 |
| `me_config.py` | `me.yaml`을 읽고 검사한다. `python me_config.py`는 무료 점검 |
| `birth.py` · `chart_factory.py` | 출생정보 → 명식(표준시 보정·진태양시·자시 후보·대운·출생 천궁도) |
| `saju_core.py` | 일진·연주·월주·십성·충합·절기 계산 |
| `astro_core.py` | 오늘 행성 위치와 출생 천궁도 사이의 주요 각·역행 |
| `interpret.py` | Claude에게 보내는 프롬프트와 호출 |
| `quality_gate.py` | 발송 전 품질 게이트 |
| `notify.py` | 텔레그램 발송(재시도 포함) |
| `run_daily.py` | 전체 순서 — 계산 → 해석 → 게이트 → 발송 → 최근 발송문 저장 |
| `find_chat_id.py` | 텔레그램 chat id 찾기 |
| `tests/` | 회귀 테스트(매일 발송 전에 먼저 돈다) |
| `requirements.txt` | 매일 알림에 필요한 패키지 — anthropic(Claude API) · ephem — 서양 별자리 트랜짓(천체력, 데이터파일 불필요) · PyYAML(me.yaml 읽기) · pytest(발송 전 회귀 테스트). 모든 패키지에 메이저 버전 상한을 둡니다(새 메이저 버전이 어느 날 깔려 알림이 조용히 멈추지 않게) |
| `requirements-verify.txt` | 선택 — 계산 검증 도구용(skyfield·jplephem). 매일 알림에는 필요 없습니다 |
| `tools/verify_with_de421.py` | 선택 — 계산 검증(NASA JPL 천문력 DE421과 대조, 수업 4장 3강). 의존성은 `requirements-verify.txt` |
| `state/` | 사람별 최근 7일 발송문. 첫 발송 때 생기고 워크플로가 커밋한다 |

`interpret.py`의 시스템 프롬프트(말투·규칙)를 고치면 `tests/test_interpret.py`의 톤 규칙 테스트 문구도 같이 고칩니다. 테스트가 깨지면 그날 아침 발송이 돌지 않습니다.
